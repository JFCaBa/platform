# What Platform website: search visibility — plan

**Goal:** whatplatform.uk gets found in Google and Bing for "<station> platforms / departures"
searches: every station has its own crawlable page, a sitemap lists them, and the site is
registered in Google Search Console and Bing Webmaster Tools.

**Why this shape:** today every URL serves the same `index.html` shell (same title, no canonical,
content only after JS). Google renders JS, but 2,627 identical shells are thin and "soft 404"
prone, and unknown codes answer 200. KISS fix without a framework or build step for the app:
pre-render one static HTML file per station from the station list the server already has.

**Tech:** Python 3 stdlib generator (like `pipeline/build_stations.py`), tests with `unittest`
(runs on the Mac's 3.9 and the VPS's 3.12). nginx serves the generated files. No change to the
board's JS logic except one small hook.

## Decisions

1. **Generator** `deploy/web/build_pages.py --stations FILE --site site/ --out DIR`
   (default out `/opt/platform/web`), writes:
   - `station/{CRS}.html` for every station: `site/index.html` with the head block and the
     pre-rendered block (between `<!--seo:head-->…<!--/seo:head-->` and
     `<!--seo:body-->…<!--/seo:body-->` markers) replaced.
   - `stations.html`: all stations A–Z, grouped by first letter, links to `/station/{CRS}`.
   - `sitemap.xml`: `/`, `/stations`, `/privacy` and every `/station/{CRS}`; `<lastmod>` = the
     station list's `generated` date for stations and the A–Z page, none for `/` and `/privacy`.
   - Atomic: builds into `DIR.new`, then swaps (`DIR` → `DIR.old`, `DIR.new` → `DIR`, remove
     old). Refuses (exit 1, old files stay) if fewer than 2,000 stations or a marker is missing.
   - All text HTML-escaped (`html.escape`), JSON-LD via `json.dumps` with `<`, `>`, `&` escaped
     as `<` etc. so a station name can never close the script.
2. **Station page content** (static, readable without JS):
   - `<title>{Name} ({CRS}) — live departures and platforms | What Platform</title>` (same as
     app.js `setMeta`), meta description "Live departures from {Name} ({CRS}): which platform,
     delays and cancellations, updated every 30 seconds. Free, no sign-up.",
     `<link rel="canonical" href="https://whatplatform.uk/station/{CRS}">`, Open Graph
     (title, description, url, type website, image apple-touch-icon).
   - JSON-LD `TrainStation` {name, identifier CRS, url, geo lat/lon}.
   - Inside `<main id="app">`: top bar, `<h1 class="station">{Name}</h1>`, one paragraph of
     text, the App Store badge. app.js replaces it with the live board as now.
   - Outside main, `<aside id="extra" data-path="/station/{CRS}">`: "Nearby stations" — the 6
     nearest by haversine, each with distance (km/mi like `formatDistance`), and a link to
     "All stations A–Z". Stays after JS renders, so the links are in the rendered DOM too.
3. **Home** (`site/index.html` itself): canonical `/`, OG tags, JSON-LD `WebSite` +
   `MobileApplication` (iOS, TravelApplication, free, App Store URL); `<main>` pre-renders the
   heading, tagline, badge and the popular-station links (static, same list as app.js POPULAR);
   `<aside id="extra" data-path="/">` with a short "How it works" and the A–Z link. `<noscript>`
   kept for the JS message.
4. **app.js hook:** at the start of `route()`, remove `#extra` when its `data-path` is not
   `location.pathname` (after canonicalisation), so in-app navigation never shows another
   station's nearby list. Pure helper `extraBelongs(dataPath, pathname)` in `route.js`, tested.
5. **nginx** (website server block):
   - `location ~ "^/station/([A-Z]{3})/?$"` → `root /opt/platform/web; try_files /station/$1.html =404;`
   - any other `/station/xxx` (lowercase, unknown code) → 404 status with the shell:
     `error_page 404 /404-shell;` + `location = /404-shell { internal; try_files /index.html =404; }`
     so the JS still shows "Station not found" / fixes lowercase, but Google sees a real 404.
   - `location = /stations` → `/opt/platform/web/stations.html`; `location = /sitemap.xml` →
     `/opt/platform/web/sitemap.xml`; `location = /robots.txt` → `site/robots.txt`.
   - No `add_header` in these locations, so they inherit the server's CSP/HSTS/no-cache.
     JSON-LD (`type="application/ld+json"`) is data, not script, so CSP does not block it.
6. **robots.txt** (`site/robots.txt`): allow all, `Sitemap: https://whatplatform.uk/sitemap.xml`.
   `api.whatplatform.uk` gets no robots.txt: Google must be able to fetch the API when it renders.
7. **When it runs:** `deploy/stations/refresh.sh` calls the generator after rebuilding
   stations.json (monthly); `deploy/README.md` Update section adds it after `git pull` (template
   changes). dev.py serves generated pages from a local out dir when present.
8. **Search engines** (after deploy, in the browser with the user's sessions):
   - Google Search Console: Domain property `whatplatform.uk` (DNS TXT already present), submit
     the sitemap, request indexing of `/`, `/stations` and a handful of big stations.
   - Bing Webmaster Tools: import from Search Console, submit the sitemap.
   - IndexNow is not added (Bing reads the sitemap; KISS).

## Tasks

1. Generator + tests (`deploy/web/test_build_pages.py`): page per station with escaped name,
   canonical, title, JSON-LD parses and is escaped, 6 nearest excluding itself sorted by
   distance, A–Z page, sitemap URL count and XML well-formed, refuses <2,000 stations / missing
   marker with old output intact, atomic swap.
2. `index.html` markers + home static content + `robots.txt` + `style.css` for the aside/A–Z;
   `route.js` `extraBelongs` + test; app.js hook.
3. nginx + refresh.sh + README + dev.py.
4. Deploy (git pull, create `/opt/platform/web` owned by ubuntu, run generator, nginx -t,
   reload) and check with curl: station 200 with its title, unknown/lowercase 404, sitemap,
   robots, CSP present, Googlebot UA 200.
5. Search Console + Bing as in decision 8.

## Review focus

- A station name with `&`, `'` or `</script>` breaks HTML or JSON-LD.
- Unknown CRS answering 200 (soft 404) or the 404 path breaking the JS fallback.
- The generator half-writing the output dir on failure.
- In-app navigation leaving the previous station's nearby list.
- Security headers missing on the new locations.

## Consenso rulings (26-11-2026, codex + agy)

- **Accepted (both):** the two-rename swap leaves a window with no DIR. Publish instead by
  building into `DIR-<timestamp>/` and replacing the symlink `DIR` with `os.replace` of a temporary
  symlink (atomic). Keep the previous build, delete older ones; `fcntl` lock against two runs.
- **Already so:** the JSON-LD is `json.dumps` with `<`, `>`, `&` as `<` `>` `&`
  (JSON escapes, not HTML entities), so "Elephant & Castle" stays intact.
- **Already so:** paths not matching `/station/[A-Z]{3}` fall to the server's `location / { return 404; }`.
- **Rejected, 301 for lowercase:** nginx cannot uppercase without a module or a generated map;
  nobody links lowercase codes (the app and site always use uppercase). Lowercase gets the 404
  shell, where the JS still opens the station for a person. Cost if wrong: an odd inbound link
  does not pass to the canonical page.
- **Rejected, re-render #extra in JS:** the links in `#extra` are plain links (full page load),
  so each station page loads its own nearby list; it is only dropped after in-app navigation
  (search, popular), where it would be stale. Cost if wrong: fewer nearby links after in-app moves.
- **Rejected, robots Disallow on the API:** Google needs the API to render the board; the API
  is cached per station and crawlers are not counted as people. Cost if wrong: some extra API load.
- **Already so:** the server's security headers use `always`, so they reach 404s too.
